# B 站视频下载器

一个跑在本机的 B 站视频下载工具：**双击 `启动.bat` 打开一个独立应用窗口**，粘贴链接，自动解析，直接下载到本地。

不需要注册任何账号，不需要第三方网站，所有解析都在你自己电脑上完成。界面是自绘的液态玻璃风格窗口（Windows 上由系统自带的 WebView2 渲染），没有浏览器地址栏，也不占用浏览器标签页。

## 功能

- **链接自动识别**：BV 号、av 号、完整链接、`b23.tv` 短链、App 分享文案，粘进去就能解析（甚至可以只粘贴一整段带链接的分享文字）
- **清晰度选择**：列出该视频真实可下载的每一档画质（8K / 4K / 1080P60 / 1080P / 720P / 480P / 360P），并标注哪些需要登录
- **多线程加速**：把文件切成多段并行下载，明显快于浏览器单线程抓取
- **音视频自动合并**：B 站高清是音视频分离的 DASH 流，工具会自动下载两条流并用 ffmpeg 无损合并为 mp4
- **多 P 支持**：可分集下载，也可一键下载全部 P
- **仅提取音频**：可选导出 M4A（原始音质）或 MP3（192kbps 转码）
- **编码可选**：同画质下可在 H.264 / H.265 / AV1 之间选择，默认 H.264（兼容性最好）
- **断点续传**：分片下载失败会自动重试并续传已下载部分
- **实时进度**：显示百分比、速度、剩余大小，支持取消

## 快速开始

**方式一：直接用打包好的 exe（推荐，不需要装 Python）**

双击 **`dist\B站视频下载器.exe`** 即可。程序、依赖、ffmpeg 全部打包在这一个文件里，
第一次启动会解压到临时目录（约 3 秒），之后每次启动同样快。

下载的文件和配置都放在 **exe 同目录**下的 `downloads\` 与 `config.json`，整个文件夹拷走就能换电脑用。

**方式二：从源码运行（需要 Python 3.9+）**

1. 双击 **`启动.bat`**
2. 依赖齐全时会直接弹应用窗口；缺依赖时会先出现一个**自带进度条的安装窗口**（无控制台），装完自动启动
3. 之后粘贴链接即可

窗口操作：拖拽标题栏移动，双击标题栏最大化/还原，右上角是最小化/最大化/关闭，也可以直接拖窗口边缘改变大小。

> 想用浏览器版（比如在另一台设备上访问）：`python run.py`，会自动打开 http://127.0.0.1:8765。同一套界面，只是没有窗口外壳。

> 需要 Python 3.9 及以上。如果没有，去 https://www.python.org/downloads/ 安装，安装时**务必勾选 "Add Python to PATH"**。

ffmpeg 无需单独安装：首次运行会通过 `imageio-ffmpeg` 自带一份，开箱即用。

## 登录与高清画质

未登录状态下，B 站只放行 480P 及以下。

**最省事的方式：点界面右上角的「未登录 · 点击登录」**（或设置里的「打开 B 站登录窗口」）。

弹出的登录窗口是**完整的桌面版页面**（默认约 1220×660，可以自由缩放），左边是扫码登录、右边一排是「密码登录 / 短信登录」加账号密码框，还有微信 / 微博 / QQ 登录 —— 和浏览器里打开的一模一样，不用在小窗口里凑合。

扫码或登录成功后，程序会自动把 Cookie 取回来保存、关掉窗口，主界面状态随之变成「已登录」。

**如果你是在解析完视频之后才登录的**，程序会立刻用新身份重新拉一次码率，并把清晰度自动切到当前可用的最高档（比如从 480P 直接跳到 1080P），不需要你再点一次「解析」。手动在设置里粘贴 Cookie 生效时也一样。

如果二维码加载失败（网络抖动时偶发），程序会在后台自动点一次刷新，不需要你手动处理。

原理：登录窗口本身就是一个内嵌浏览器，登录成功后主程序轮询该窗口的 Cookie，读到 `SESSDATA` 立刻写进本机 `config.json`。

如果自动登录不可用，也可以手动填：

1. 浏览器登录 [bilibili.com](https://www.bilibili.com)
2. 按 `F12` → `Application`（应用）→ `Cookies` → `https://www.bilibili.com`
3. 找到 `SESSDATA`，复制它的值
4. 点右上角齿轮 → 粘贴到输入框 → 保存

Cookie 只保存在本机 `config.json` 里，不会上传到任何地方。4K、8K、杜比视界等还需要对应的大会员权限。

## 文件存放位置

默认在项目下的 `downloads/` 目录，界面右上角「打开下载目录」可以直接跳转。

文件名格式为 `视频标题.mp4`，多 P 视频会带上 `- P1 分集名`。重名文件会自动加序号，不会覆盖。

## 常见问题

**解析失败 / 提示需要登录**
B 站接口有风控，偶尔失败重试一次即可。如果持续失败，多半是 Cookie 过期，重新获取一次 SESSDATA。

**解析一直转圈、报网络超时**
工具默认直连 B 站，不读系统代理。如果你的网络必须走代理才能访问外网（海外网络、公司内网），在设置里勾选「通过系统代理访问 B 站」；反过来，如果勾选了但本地其实不需要代理，也会导致超时，取消勾选再试。

**为什么下载下来只有 480P**
未登录。见上面「下载高清画质」。

**番剧 / 影视专区下载不了**
番剧走的是另一套 PGC 接口，且大多有版权与会员限制，当前版本不支持。本工具面向普通投稿视频。

**双击后没反应 / 窗口空白**
窗口用的是系统自带的 WebView2 内核。Win11 和较新的 Win10 都自带；如果缺失，装一下 Evergreen Runtime 即可：https://developer.microsoft.com/microsoft-edge/webview2/ 。另外 `pythonw` 启动不带控制台，出错时会弹系统提示框，按提示处理。

**双击后没反应 / 窗口空白**
窗口用的是系统自带的 WebView2 内核。Win11 和较新的 Win10 都自带；如果缺失，装一下 Evergreen Runtime 即可：https://developer.microsoft.com/microsoft-edge/webview2/ 。另外 `pythonw` 启动不带控制台，出错时会弹系统提示框，按提示处理。

**提示缺少 ffmpeg**
执行 `python -m pip install imageio-ffmpeg` 即可。

**想让速度更快**
设置里把线程数调到 8～16。再高容易被 CDN 限速，反而变慢。

## 目录结构

```
bilidownload/
├── 启动.bat            # 源码版启动（无控制台，缺依赖时弹进度窗）
├── 打包.bat            # 一键打包成 exe
├── bootstrap.py        # 依赖检查 + 自绘进度窗安装器
├── desktop.py          # 桌面窗口入口：后台起服务 + 原生窗口 + 窗口控制桥接
├── run.py              # 浏览器版入口（选端口、开浏览器）
├── app.py              # FastAPI 服务与接口
├── bili/
│   ├── wbi.py          # WBI 签名 + 请求会话
│   ├── parser.py       # 链接识别、视频信息、播放流解析
│   └── downloader.py   # 多线程下载、ffmpeg 合并、任务管理
├── static/             # 界面（玻璃视觉在 style.css，交互在 app.js）
├── assets/             # app.ico（应用图标）等资源
├── make_icon.py        # 重新生成图标
├── dist/               # 打包产物（exe）与用户数据
├── downloads/          # 下载输出目录
└── config.json         # 你的本地配置（Cookie、线程数）
```

## 窗口是怎么来的

`desktop.py` 在后台线程里跑 `app.py` 的本地服务，然后用 pywebview 开一个无系统标题栏的窗口（Windows 上是 WebView2 内核），前端还是那套 HTML/CSS/JS，所以界面能保持完全一致的细节控制。

几个为「像原生应用」做的事：

- 标题栏自绘：胶囊 logo、应用名、最小化/最大化/关闭，拖动区用 pywebview 的 `pywebview-drag-region`
- 最大化按工作区铺满（系统自带最大化对无边框窗口会盖住任务栏），还原时回到原来的位置
- 无边框窗口默认不能拉边缘改大小，启动后补上 `WS_THICKFRAME` 样式位，视觉仍是纯自绘
- 「保存到本地」走系统原生另存为对话框，不是浏览器下载
- 窗口尺寸按屏幕工作区自动计算，并考虑系统缩放（125% / 150%）

## 打包成 exe

双击 **`打包.bat`**（或执行 `python -m PyInstaller BiliDownloader.spec`），产物在 `dist\`：

- `dist\BiliDownloader.exe`：英文名原始产物
- `dist\B站视频下载器.exe`：改名后的成品，图标、行为完全一致

打包用 PyInstaller 单文件模式（`--onefile --windowed`），会把：

- `static\`（界面）与 `assets\`（图标）打进资源目录
- `imageio-ffmpeg` 自带的 ffmpeg 一起打进去（所以有 50MB+）
- pywebview 依赖的 pythonnet / clr_loader 一并收集

改完代码重新打包即可，注意 `dist\downloads` 与 `dist\config.json` 是用户数据，不要打进包里。

## 应用图标

`assets\app.ico` 是按需求画的：粉色圆角底 + 白描边的小电视 + 天线 + 中间向下箭头，
同时带 16/20/24/32/40/48/64/128/256 多尺寸（任务栏、资源管理器、Alt-Tab 都清晰）。

想改样式就编辑 `make_icon.py` 后执行 `python make_icon.py` 重新生成。
运行时 `desktop.py` 会把这个 ico 通过 `WM_SETICON` 设到窗口上（WinForms 窗口不会自动继承 exe 图标）。

## 首次启动的依赖安装窗口

源码版第一次运行需要装依赖。为了不弹黑框，安装器 `bootstrap.py` 是这样实现的：

- **只用标准库**：那时第三方库还没装，连 tkinter 都不一定有（这个环境就没有）
- **分层窗口自绘**：`UpdateLayeredWindow` + 逐像素抗锯齿圆角，所以能和主界面同一套视觉；阴影用窗口类的 `CS_DROPSHADOW` 交给系统
- **pip 在后台线程跑**，输出被解析成进度：`Collecting` 阶段用渐近曲线（先快后慢，不会卡在 99%），`Installing collected packages` 阶段推进到 96%，装完校验后再到 100%
- 全程 `CREATE_NO_WINDOW`，不会有任何控制台窗口
- 依赖齐全时这个窗口根本不出现，直接启动主程序

调试界面可以执行 `python bootstrap.py --preview`，它只放演示进度、不真的装东西。

## 解析进度条

点「解析」后，搜索框下方会出现一条玻璃质感的进度条，显示当前阶段和百分比。

解析本身是「一个请求干完所有事」，前端拿不到中途进度，所以后端把阶段写进一个全局状态，前端在请求进行时每 180ms 轮询一次：

| 进度 | 阶段 |
|---|---|
| 12% | 正在识别链接 |
| 26% | 正在获取视频信息 |
| 58% | 正在拉取播放流 |
| 90% | 正在整理清晰度 |
| 100% | 解析完成（转绿） |

几个细节：

- 显示值用缓动去追真实进度（并在目标之上留一小段余量），阶段跳变时才不会一格一格地弹
- 完成文案等条子真正走满才切，避免出现「已完成」停在 60% 的怪象
- 结果卡等进度条收完再渲染，否则它占据的那一行高度会让下面的内容先被顶下去、再弹回来
- 失败时进度条停住转红并给出原因，1.2 秒后收起
- 超过 8 秒没响应，阶段文案会变成「网络较慢，正在重试…」

## 界面为什么用自绘下拉

清晰度、编码、音轨这几个选择器不是原生 `<select>`，而是自己画的浮层。

原因：WebView2 的原生下拉弹窗在无边框窗口里根本弹不出来（点上去没反应），这正是第一版"选了没效果"的原因；另外系统菜单是浅色的，和整套玻璃风格也不搭。

自绘版还顺带支持了：选项里直接标出「需登录」并置灰、预计文件大小、键盘上下键选择、点空白/按 Esc 关闭。

## 液态玻璃（Liquid Glass）视觉说明

界面里每块玻璃由三层构成：

1. **半透明渐变底 + `backdrop-filter`**：模糊并提高背后背景光晕的饱和度，形成折射感
2. **`::before` 渐变描边**：模拟玻璃切面的镜面反射，左上最亮、右下回光
3. **`::after` 跟随指针的高光**：坐标写进 CSS 变量 `--mx/--my`，高光随鼠标在玻璃面滑动

背景是四层缓慢漂移的彩色光斑（粉、靛蓝、青），玻璃需要「有东西可以折射」才有质感 —— 纯色背景下玻璃会显得像一张灰卡片。

> Windows 10 不会给无边框窗口切圆角（Win11 才会），所以窗口四角是直角，用一圈约 5% 白色的发丝描边让直边看起来是刻意的玻璃裁边。

## 技术说明

B 站 2023 年后的 Web 接口都要求 WBI 签名：从 `nav` 接口拿到 `img_key` / `sub_key`，按固定重排表拼出 `mixin_key`，再对排序后的参数做 MD5 得到 `w_rid`。本工具完整实现了这套签名，所以能直接拿到 `playurl` 的 DASH 流地址。

下载时按 `Range` 把文件切成多段并发拉取，再顺序拼接；音视频两条流下载完成后用 `ffmpeg -c copy` 无损封装为 mp4，不重新编码，所以速度只取决于网速。
