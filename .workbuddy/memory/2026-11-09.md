# 2026-11-09

## 改造为桌面窗口程序 + 液态玻璃视觉

需求：把网页版改成可打开的独立窗口，整体按键要液态玻璃效果。

### 架构决定
- 新增 `desktop.py`：后台线程跑 uvicorn（沿用 `app.py`），前台用 pywebview 6.2.1 开无边框窗口（Windows 上是系统 WebView2 内核，本机运行时 157.x）。
- 前端仍是同一套 `static/`，通过 `?desktop=1` 打 `html.desktop` 标记，首帧前用内联脚本打上，避免闪烁。
- `run.py` 保留为浏览器版入口；`启动.bat` 改为 `start "" pythonw desktop.py`。

### 踩过的坑（重要，别再犯）
1. **pywebview 会递归遍历 js_api 对象的公开属性**（`webview/util.py` 的 `inject_pywebview`），窗口引用必须存成 `self._window`，否则日志刷屏 + 启动巨慢。
2. **无边框窗口最大化会盖住任务栏**。改为自己按 `SPI_GETWORKAREA` 铺满，并记住原位置还原。
3. **frameless 窗口没有 `WS_THICKFRAME`，不能拉边缘改大小**。启动后（`webview.start(func)` 回调里，要重试等待窗口出现）补上该样式位 + `SWP_FRAMECHANGED`，视觉仍是纯自绘。
4. **`work_area()` 必须先确认 DPI 感知再取工作区**，否则拿到的是虚拟化坐标，再除缩放会算小一圈，窗口退到 min_size。
5. **`GetDeviceCaps` 首次调用会返回错值（192 而非 144）**，改用 `GetDpiForSystem` 并缓存。
6. **批处理里直接写 `pythonw desktop.py` 会让 cmd 一直等待**（黑窗不关），必须 `start "" pythonw desktop.py`。
7. **`for /f` 里嵌双引号取 pythonw 路径不可靠**，直接用 PATH 里的 `pythonw`。
8. 依赖探测改用 `importlib.util.find_spec` 而不是真 import，启动从 3s 降到 1s。
9. 窗口带系统投影边框，实际内容区比请求尺寸小约 8~20px（1220x668 → 1206x631）。
10. Windows 10 不会给无边框窗口切圆角（只有 Win11 会），所以用一圈 5% 白色发丝描边当"玻璃裁边"。
11. 弹窗关闭用 `e.target.dataset.close` 时，点 × 图标（svg/path）失效，要改 `closest("[data-close]")`。

### 液态玻璃实现
- 三层：`background-color` + `--glass-grad` 半透明渐变、`backdrop-filter: blur(26px) saturate(180%)`；`::before` 渐变描边（左上亮、右下回光，`mask-composite: exclude`）；`::after` 指针高光（`--mx/--my`，靠 `pointermove` 委托 + rAF 节流）。
- 背景必须有东西可折射：`.aurora` 三团缓慢漂移的彩色光斑 + 噪点。纯色背景上玻璃会像灰卡片。
- `::after` 用 `z-index: -1` + 父级 `isolation: isolate`，才能压在背景上、文字下。

### 本机环境
- Windows 10 19045，1920x1080 @150% 缩放 → 工作区逻辑尺寸 1280x680。
- 界面按 1206x631 内容区调过纵向节奏（首屏能看到任务卡）。

- 没有 WebView2 运行时的机器需要用户手动安装（README 已写）。

## 第二轮修复（同日稍晚）

用户反馈：解析后选清晰度/编码/音轨用不了；要求登录 B 站自动化拿 Cookie。

### 根因与修法
1. **原生 `<select>` 在无边框 WebView2 窗口里弹不出选项**（点上去只有 tooltip）。
   → 全部换成自绘玻璃下拉 `Dropdown` 类（`static/app.js`）：面板挂 body、`position: fixed`、键盘 ↑↓/Enter/Esc、禁用项标「需登录」、点外部关闭。
   注意 JS 里取值要改用 `dropdowns.xxx.value`，事件也由组件 dispatch。
2. **`get_cookies()` 返回的是 `http.cookies.SimpleCookie` 列表**（dict 子类，键才是 cookie 名，值是 Morsel），不是 `{name,value}` 字典。
   → `iter_cookie_pairs()` 统一拍平；只判断 `c.get('name')` 会永远拿到 None（踩过）。
3. **js_api 里 `_` 开头的方法不会暴露给 JS**，测试用接口必须用公开名。
4. 登录流程：`login_bilibili()` 用 pywebview 在运行时新建窗口打开 passport.bilibili.com，主线程每 0.7s 轮询 Cookie，拿到 SESSDATA 就写 config + 关窗 + `evaluate_js` 通知前端刷新。最多等 5 分钟，用户手动关窗返回 canceled。

### 验证方法（重要）
- **ImageGrab 截屏在窗口被遮挡/未置顶时完全不可信**（会截到别的程序，或抓到过期的 DWM 表面，让人误以为面板被裁掉）。可靠做法：`PrintWindow(hwnd, hdc, 2)`（PW_RENDERFULLCONTENT）+ GDI 取位图。
- 真实鼠标测试要点两次：第一次只是激活窗口（Windows 前台锁），第二次才落到内容。
- 编码是否真的生效，要看产物：`ffmpeg -i` 显示 hevc 才算通。

### 其他小修
- 音频模式下只剩一个控件，`.controls.single` 收窄到 360px，别拉成整行。
- 下拉弹层不叠 backdrop-filter（97% 不透明，叠了没意义还多一层合成）。
- 弹层去掉 title，否则原生 tooltip 会压住刚弹出的面板。

## 第三轮：打包 exe + 图标 + 无控制台依赖安装窗

用户要：打包成普通软件那样的 exe；首次装依赖不弹 cmd，改成带进度条的窗口；画一个"B站小电视+下箭头"的图标。

### 图标（make_icon.py）
- 1024 基准绘制后降采样，输出 assets/app.ico（9 种尺寸）+ icon.png。
- **坑：PIL 的 ImageDraw 不做 alpha 混合**，`fill=(255,255,255,30)` 会直接覆盖像素，把底图吃掉。半透明层要先画到独立 RGBA 图层再 `alpha_composite`。
- 箭头用 `rounded_rectangle(corners=(True,True,False,False))` + 三角，底端与三角重叠 2% 以免出现缺口。

### 打包（PyInstaller 6.22）
- `--onefile --windowed --icon assets/app.ico --add-data "static;static" --add-data "assets;assets" --collect-all webview/imageio_ffmpeg/pythonnet/clr_loader + hidden-import app/bili.*`
- 产物 56MB（ffmpeg 占大头），冷启动 3.0s。
- **frozen 路径**：`sys._MEIPASS` 放只读资源（static/assets），`Path(sys.executable).parent` 放用户数据（downloads/config.json），否则下载的文件会留在临时目录里消失。
- **uvicorn 不要用 "app:app" 字符串**，冻结后运行时导入容易失败，直接传 ASGI 对象。
- WinForms 窗口不会继承 exe 图标，运行时用 `WM_SETICON` + `SetClassLongPtrW(-14/-34)` 补上。

### 依赖安装窗（bootstrap.py）
环境没有 tkinter，只能纯 ctypes 自绘：分层窗口（UpdateLayeredWindow）+ 逐像素抗锯齿圆角 + CS_DROPSHADOW 系统阴影。
- **GDI 是批处理的**：画完必须 `GdiFlush()` 再读 DIB 像素，否则读到旧数据（表现为背景全黑、进度条被覆盖）。
- **`msimg32.GradientFill` 对 32bpp DIB 返回成功但完全不写像素**，改用 Python 逐行生成渐变，反而更可控。
- **`CreatePen(1, ...)` 的 1 是 PS_DASH 不是 PS_SOLID(0)**，画出来是虚线（进度条下方那排小点就是这么来的）。
- `DrawTextW` 在 **user32**，不在 gdi32。
- 进度用渐近曲线 `8 + 72*(1-exp(-n/(total*1.6)))`，再加安装阶段推进到 96%，避免卡 99%。
- 加 `--preview` 参数可单独看界面，不用真装依赖。
- 验证方式：把 REQUIREMENTS 指向临时文件装一个小包走通成功路径，再指向不存在的包验证错误态。

### 其他
- 启动器：`启动.bat` 只负责找 python 并 `start "" pythonw bootstrap.py` 后退出；尝试过写 .vbs 做零控制台，被安全策略拦截（LOLBin），放弃。

## 第四轮：登录窗口适配（同日 00:30）

反馈：登录窗口太小/不适配，要能看到二维码和密码登录。

### 改动
- 窗口从 520×740 改为按工作区自适应：`width = max(880, min(1220, avail_w-40))`，`height = max(560, min(660, avail_h-20))`，本机即 1220×660；`min_size=(880,560)`，可自由缩放。
- 原因：B 站登录页在 <900px 宽时会退化成窄版，右侧「密码登录/短信登录」被挤掉；1220 宽正好是桌面版布局，扫码区在左、密码表单在右同屏显示。
- 新增二维码自动纠偏：每 0.7s 的轮询里，在第 9/18/27 次 tick（约 6/12/19s）注入一段 JS，若页面出现「点击刷新/二维码失效」就替用户点一下。

### 验证要点
- 用 `ctx.pages` 能拿到 passport 页（此前拿不到是因为窗口还没创建完成），可以直接 evaluate JS 查 DOM。
- 二维码真实元素是 `img[src^="data:image"]` 140×140，外面套 `.login-scan__qrcode`；过期时会盖一个 `.scan-tips-icon` 浮层。
- **别在窗口开很久之后截图判断**：二维码约 3 分钟就过期，看起来像"一直没加载"。实测开场 8~16 秒内即出码。
- 打包后的 exe 同样验证过登录窗口尺寸（1830×990 物理 = 1220×660 逻辑）。

## 第五轮：登录后自动刷新码率（00:48）

反馈：先解析（未登录只有 480P）再登录，码率列表不更新，必须手动重新解析才有 1080P。

### 原因
登录成功后只调了 `loadSettings()` 刷状态角标，没有重新请求 `/api/streams`，所以画质下拉还是登录前那份未登录数据。

### 改法（static/app.js）
- 新增 `refreshAfterLogin()`：用当前 bvid/cid 重新 POST `/api/streams`，重建下拉，并**自动选中最高档**（渲染逻辑会保留旧值，不显式切的话仍停在 480P）。
- 三个入口都接上：Python 的 `onLoginStateChanged` 回调、登录接口返回 ok、设置里手动保存 Cookie 成功。
- 两个入口会重复触发，用时间戳去重（1.5s 内只跑一次）。

### 验证（用真实账号，不是 mock）
1. 清空 sessdata → 解析 → 480P 清晰
2. 恢复真实 Cookie → 触发 `onLoginStateChanged` → 自动变成 **1080P 高清**，列表出现 1080P/720P/480P/360P，4K 与 1080P60 标记需登录
3. 提示语：「已按登录状态刷新码率，当前最高可用：1080P 高清」

### 注意
- `dist/config.json` 里是**用户真实的 SESSDATA**（用户自己扫码登录成功留下的）。清理临时文件时不要误删，删了要按原值恢复。
- 测试时用 `POST /api/settings` 改 sessdata 前后要备份 config.json。

## 第六轮：液态玻璃高光"卡住"（01:10）

反馈：鼠标移进玻璃控件有跟随高光，移出后高光停在最后位置不恢复。

### 原因
高光位置写在行内 `--mx/--my` 上，而 `pointermove` 只负责写入、没人负责清除；`::after` 又常驻 `opacity: .85`，所以光斑永远留在鼠标最后停留处。

### 改法
- CSS：`.glass:not(:hover)::after { opacity: 0 }`，配合已有的 opacity 过渡淡出；顺带对 `@media (hover: none)` 关闭跟随高光（触屏无意义）。
- JS：新增 `pointerout` 委托，指针真正离开元素（`relatedTarget` 不在元素内部）时移除 `--mx/--my` 行内样式，回落到 CSS 默认位置；窗口 `blur` 时全量复位。

### 验证（真实鼠标移动 + 读计算样式）
```
移入按钮: --mx=39px  --my=19.7px  ::after opacity 0.85
移出之后: --mx=(空)  --my=(空)    ::after opacity 0.00
再次移入: --mx=39px  --my=19.7px  ::after opacity 0.85
```

### 修正（同轮内）：`:not(:hover)` 方案不可用
先试的 CSS 方案 `.glass:not(:hover)::after { opacity: 0 }` 在 WebView2 里**行为相反**：元素悬停时该规则仍匹配（opacity 变 0），移出后才回到 0.85。
排查手段：用 `document.styleSheets` 遍历删除该规则后，悬停态立刻变回 0.85，由此确认是规则匹配问题，不是过渡或优先级。
最终改为**由 JS 维护 `.sheen-on` 类**：`pointerover` 沿祖先链加类、`pointerout` 移除（`relatedTarget` 在元素内则跳过），CSS 只写 `.glass.sheen-on::after { opacity: .85 }`，基础态为 0。不再依赖 `:hover`。

最终验收（计算样式 + 像素差双证）：
```
初始   on=false  --mx=空  opacity 0.00
移入   on=true   --mx=40.7px  opacity 0.85   祖先链 parseForm+btnParse 同时亮
移出   on=false  --mx=空  opacity 0.00       亮点清空
再入   on=true   --mx=40.7px  opacity 0.85
冻结动画后按钮区域平均亮度：悬停 74.9 / 移出 72.0
```
