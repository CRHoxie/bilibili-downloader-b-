## B 站视频下载工具（项目首个完整功能）

**目标**：用户要一个「粘贴视频链接 → 自动解析 → 下载」的本地工具。

**技术方案**（已验证跑通）：
- 后端 FastAPI + 前端原生 HTML/CSS/JS 单页，本地服务 127.0.0.1:8765
- 解析：自研 B 站 Web API 客户端，实现 **WBI 签名**（`img_key`+`sub_key` → MIXIN_KEY_ENC_TAB 重排 → mixin_key → 参数排序后 MD5 得 `w_rid`）
  - 取流接口 `/x/player/wbi/playurl`，`fnval=4048&fourk=1` 拿到 DASH（音视频分离）
- 下载：按 Range 多线程分块（默认 8 线程）+ 顺序拼接 + 失败续传
- 合并：ffmpeg `-c copy` 无损封装 mp4；ffmpeg 二进制来自 `imageio-ffmpeg`，无需用户安装
- 任务：内存任务表 + 前端 700ms 轮询，Semaphore(3) 限制并发

**关键坑位记录**：
1. 本机 `python` 指向 WorkBuddy 内置 Python（`.workbuddy/binaries/python`），而 `pip` 指向系统 Python —— 必须用 `python -m pip` 才一致。
2. `nav` 接口未登录返回 code -101，但 data 里带 WBI 密钥 → `get()` 必须支持 `allow_codes=(-101,)` 否则取密钥失败。
3. **Windows .bat 编码**：cmd 按系统 ANSI(936) 读取批处理，UTF-8 中文会把括号块解析坏 → 启动.bat 必须存成 **GBK + CRLF**，且用 `goto` 标签代替嵌套 if/延迟展开。
4. 未登录只能拿到 480P 及以下；`accept_quality` 列出的高清需登录/大会员，UI 要做「需登录」禁用项提示。
5. 环境里 requests 访问 127.0.0.1 会走代理 → 本地测试用 `session.trust_env=False`。

**文件**：
- `app.py`（接口）、`run.py`（启动/选端口/开浏览器）、`启动.bat`（GBK）
- `bili/wbi.py`、`bili/parser.py`、`bili/downloader.py`
- `static/index.html`、`style.css`、`app.js`

**已实现功能**：链接/BV/av/b23 短链/分享文案识别、清晰度选择、编码选择（H.264/HEVC/AV1）、音轨选择、多 P 分集 + 批量下载、仅音频（M4A/MP3）、Cookie 解锁高清、实时进度/速度/取消、打开下载目录。

**未做**：番剧/PGC（ep/ss 链接会提示不支持）。

## 追加：用 BV1p2Tp6REay（奶龙大笑）实测后修的三个问题

1. **音轨默认选错**（真 bug）：原先按 `bandwidth` 降序排音轨，但很多老视频各档音轨带宽几乎相同（都 ~64kbps），导致默认选中 64K。改为按音轨 id 降序：30251 Hi-Res > 30250 杜比 > 30280 192K > 30232 132K > 30216 64K。
2. **解析卡 70 秒**：`_ensure_buvid()` 里的 `/x/frontend/finger/spi` 偶发挂起，又被 `get()` 的 3 次重试放大。改为独立裸请求 + (3,3) 超时 + 绝不重试，失败静默跳过（buvid 只是降风控的增强项，非必需）。
3. **系统代理**：环境变量里的 HTTP_PROXY 会让 requests 请求被劫持/挂死（curl 正常）。B 站是国内站点，`Session.trust_env` 默认关掉直连；设置里加「通过系统代理访问 B 站」开关给海外/内网用户。
   - 注意：`downloader.make_session()` 也要同步 `trust_env`，否则下载流仍走代理。

**实测结果**：19 秒视频，480P，353KB，1.6 秒下完；产物 h264 852x480 + aac 44.1kHz 立体声，时长 18.03s 正常。
